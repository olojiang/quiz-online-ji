## 为什么要做这个项目？

开过月度会、全员会、分享会的人大概都遇到过这些场面：

| 现场的痛点 | 常见结果 |
|---|---|
| 想提问的人不好意思举手，敢举手的总是那几位 | 真正关心的问题没人问出口 |
| 问题靠纸条、微信群、会后私聊收集 | 散落各处，重复多，主持人临场挑不过来 |
| 收上来的内容没人把关 | 跑题、灌水、不合适的话直接出现在大屏上 |
| 现成工具要么要进视频会议、要么要注册账号、要么国内访问不稳、按人数收费 | 参会者嫌麻烦，组织者嫌贵 |
| 会开完就散了 | 大家关心什么、参与度如何，没有数据沉淀 |

**Quiz Online Ji 想解决的就是这一条链路**：让每个人都能低门槛地提问，让组织者有把关和控场的能力，让会后留下可复盘的数据。

```
会前开放链接 → 嘉宾扫码，只填姓名就能提问 → 自动过滤 + 人工预审
            → 审核通过后全员可见、点赞、按热度排序 → 大屏展示与现场互动 → 活动报告
```

## 亮点

- **嘉宾零门槛**：不用下载 App、不用注册、不用进视频会议。扫码或打开链接，填个名字就能参与。
- **先审后上墙**：自动过滤（敏感词、重复、刷屏、链接）+ 人工预审，大屏上只出现你放行的内容。
- **热度说话**：全员可见、点赞、热门 / 最新排序，现场最想听的问题自然浮到最上面。
- **会前就开始**：活动开始前就能开放提问，主持人提前看到大家关心什么。
- **一块大屏控全场**：二维码、欢迎页 / 互动频道切换、置顶、精选、标记已回答、缩放全屏，都在投屏端一键完成。
- **角色清晰分工**：活动管理员、审核员、主持人各司其职，权限在服务端逐一校验；每个角色都有一份说人话的帮助文档。
- **一键开始 / 结束活动**：控制台顶部和活动列表都能直接切换状态，结束前二次确认。
- **现场抽奖**：从参与嘉宾中随机抽取获奖者，大屏滚动揭晓，中奖嘉宾手机上弹出祝贺；支持补抽、作废、重置，结果进报告。
- **会后自动出报告**：参与人数、活跃度、互动分布、参与趋势、贡献排行、热门提问，一键导出 CSV / Excel，也能生成只读分享链接。
- **好看且统一**：嘉宾端、投屏端各自选主题色，系统自动推导整套协调配色并保证文字对比度。
- **链接可管可控**：所有链接都是随机 hash，可按渠道打标签、统计访问、随时作废，不暴露内部 ID。
- **为国内网络考虑**：不依赖任何外部 CDN、字体或统计脚本，绑定自有域名即可在国内访问。
- **中文 / English** 一键切换，默认中文。

## 快速上手

1. 打开 <https://quiz-online-ji.vercel.app>，**免费注册**一个账号（系统第一个账号请走 `/setup` 成为超级管理员）。
2. 在「我的活动」点 **创建活动**，填写名称和日期。活动会自动带一个「提问」。
3. 进入活动控制台，点右上角 **嘉宾端** 复制链接或打开二维码，会前发给参会者。
4. 问题会出现在 **待审核**，点 ✓ 放行；也可以打开 **自动审核**。
5. 开会时点 **投屏端 → 在新窗口中打开**，拖到大屏上全屏。点 **开始活动** 进入现场模式。
6. 会后点 **结束活动**，在 **活动报告** 里查看数据并导出。

更详细的分角色说明见站内 [帮助中心](https://quiz-online-ji.vercel.app/help)。

# 技术实现

## 技术栈
- Next.js 15 (App Router) + TypeScript + Tailwind CSS 3
- Neon Postgres via `@neondatabase/serverless`（表结构在首次请求时自动创建，`src/lib/db.ts`，全部 `CREATE TABLE IF NOT EXISTS` / `ADD COLUMN IF NOT EXISTS`）
- Auth: bcryptjs + JWT（`jose`，httpOnly cookie `qoj_token`，30 天）
- 二维码 `qrcode`、图表 `recharts`，全部打包在本站，无任何外部 CDN / 字体 / 统计脚本（便于国内访问，可直接用自定义域名代理）
- 实时：轮询（大屏 2s、嘉宾端 2.5s、控制台 3–4s），无 WebSocket

Env vars (Vercel project `quiz-online-ji`): `DATABASE_URL` (Neon), `JWT_SECRET`.

## Routes
| Page | 用途 |
|---|---|
| `/` | 首页 |
| `/setup` | 一次性初始化：系统没有任何用户时创建第一个超级管理员 |
| `/login`, `/register` | 登录 / 自助注册（注册用户 = 活动管理员，只管理自己的活动）|
| `/dashboard` | 我的活动（全部 / 进行中 / 未开始 / 已结束 筛选 + 搜索）|
| `/dashboard/events/[id]` | 活动控制台：互动、提问审核、活动报告、链接管理、成员、设置抽屉 |
| `/dashboard/users` | 用户管理（超级管理员）|
| `/dashboard/profile` | 个人信息：昵称、修改密码 |
| `/help` | 帮助中心（按角色）|
| `/g/{hash}` | 嘉宾端（手机全屏；电脑/平板 ≥768px 为居中卡片 + 主题色背景；渐变主题头部、药丸式提问栏、渐变头像、平滑切换动画，尊重「减少动态效果」）|
| `/s/{hash}` | 投屏端（大屏）|
| `/embed/{hash}` | iframe 嵌入用嘉宾端 |
| `/r/{hash}` | 只读报告分享 |

所有分享链接都是 10 位 base62 随机 hash，存于 `qoj_links`（类型 guest/screen/report/embed、标签、创建人、访问次数、失效时间）。不同类型互不通用；嘉宾 API 不返回投屏/控制台信息。失效链接返回 410 并显示「链接已失效」。数据属于活动，与链接无关。

## Roles
- 超级管理员 `super_admin`：管理所有用户与角色、所有活动
- 活动管理员 `event_admin`：创建/管理自己的活动、互动、链接、成员
- 审核员 `moderator`（按活动分配）：通过/拒绝/归档/删除、自动审核开关
- 主持人/投屏操作员 `presenter`（按活动分配）：频道切换、当前互动、上墙/置顶/精选/已回答、测验控制
- 嘉宾：无需账号（localStorage 中的随机参与者 id + 姓名）

权限在每个 API 路由服务端校验（`src/lib/auth.ts` → `eventPerms`），UI 同时隐藏无权操作。

## 活动状态快捷控制
- 状态 `qoj_events.status`：`upcoming` 未开始 / `live` 进行中 / `ended` 已结束（已结束时嘉宾端关闭提问、作答、评分）。
- `src/components/console/StatusControl.tsx`：控制台顶部状态标签（点开为三态下拉）+ 随状态变化的主按钮（开始活动 = 紫色主按钮；结束活动〔确认框，仅确认按钮为红色〕/ 重新开放 = 中性描边按钮）；「我的活动」卡片右下角为安静的灰色描边小按钮 + ⋯ 菜单。改后 toast，并重新加载；嘉宾端、投屏端下次轮询生效；「设置 → 功能设置」的活动状态读同一字段，保持同步。
- 权限（`PATCH /api/events/[id]` 服务端校验）：活动管理员（owner）/ 超级管理员可设任意状态；主持人只能设 `live` / `ended`（开始、结束、重新开放）；审核员 403。

## 评分（rate）
- 配置：标题、1–10 个评分项、评分方式 星级 / 分数、满分 3–10、允许评论、匿名展示（`validate.ts`）。
- 存储复用 `qoj_responses`（`question_index = 0`，`answer = {scores, comment}`），每位嘉宾一份，可在结束前更新；`state.closed` 控制开启/结束（`/api/interactions/[id]/rating`，主持人/活动管理员）。
- 统计 `live.ts → rateStats`：平均分（1 位小数）、分布、评论；匿名时大屏/控制台/报告/导出不含姓名。CSV：`/api/interactions/[id]/export`。
- 报告：互动类型分布、互动贡献总数（评分计为作答）、「评分结果」板块、Excel「评分结果」工作表。

## 抽奖（lottery）
- 配置（`validate.ts`）：标题、1–20 个奖项（名称唯一、名额 1–200、可选说明）、`participatedOnly`（仅限参与过互动的嘉宾）、`allowRepeat`（允许重复中奖，默认关）、`exclude`（手动移出抽奖池的参与者 id）。
- 存储：`qoj_lottery_winners`（`interaction_id, prize_index, prize_name, participant_id, nickname, round, voided, voided_at, drawn_at`；部分唯一索引保证同一奖项同一人只有一条有效记录）。作废 = `voided = true`，记录保留。
- 状态 `qoj_interactions.state`：`phase` idle 待开始 / rolling 抽奖中 / revealed 已揭晓、`prize`、`drawSeq`、`lastIds`（最近一次揭晓）。
- 操作 `POST /api/interactions/[id]/lottery`（`perms.present`：主持人、活动管理员、超级管理员；审核员 403）：`start {prize, count?}` → 大屏滚动（不产生结果）；`reveal` → 服务器用 `crypto.randomInt` 洗牌抽取剩余名额（或本轮人数），在事务 + advisory lock 中再次校验名额和不可重复中奖，名额与抽奖池人数永不超出；`cancel`、`void {winnerId}`、`exclude {pid, excluded}`、`reset`。
- 抽奖池（`src/lib/lottery.ts`）：已填姓名加入活动的嘉宾 − 手动移出 −（仅限参与时）未参与者 − 已作废的人 −（不可重复时）本抽奖已中奖者 / （可重复时）本奖项已中奖者。抽奖池为空返回 400「抽奖池为空」。
- 嘉宾端 `live.mine` 为当前嘉宾的有效中奖记录（显示「恭喜你获得 …」）；大屏额外拿到 `rollNames`（仅姓名，用于滚动动画）；只有控制台拿到 participant id。
- 已有中奖记录时不能增删奖项、名额不能低于已抽出人数；改奖项名称会同步到记录。
- 结果：控制台获奖名单；报告 `lotteries`（「抽奖结果」区块）；Excel「抽奖结果」工作表；单个抽奖 CSV `/api/interactions/[id]/export`。

## 功能开关（`src/lib/features.ts`）
- `FEATURE_GROUPS = false`：暂时没有「组别」概念。嘉宾端只填姓名；控制台不显示组别列表、组别过滤；报告/评分/导出不含按组别统计和组别列；帮助中心不提组别。服务端忽略传入的 `group` / `groups`。
- 数据库列保留不动（`qoj_events.groups`、`qoj_questions.group_name`、`qoj_participants.group_name`、评分 `answer.group`），改回 `true` 即可恢复（帮助中心文案需另行补回组别说明）。

## 大屏幕适配
- 控制台类页面（`.qoj-console`）在 ≥1600px 根字号 17px、≥2200px 18px；内容区最大宽度 1440–1600px 居中。
- 投屏端按 1920×1080 设计，按实际窗口等比缩放（0.7–2.2 倍），再叠加手动缩放。

## 预审 / 垃圾过滤
每个活动可配置敏感词、最少字数、每分钟提问上限；重复内容和链接自动标记。命中规则的问题即使开启「自动审核」也进入「待审核」，并显示原因标签。

## Themes
`src/lib/palette.ts` 从主题色推导整套配色（背景、卡片、文字、次要文字、边框、强调色、徽章、悬停），按 WCAG 对比度自动加深/选择黑白文字；投屏端 7 个预设 + 自定义，嘉宾端 6 个预设 + 自定义（电脑端卡片背后的柔和背景 `--g-backdrop*`、卡片边框 `--g-frame-border` 也由同一主题色推导；`/embed` 保持全宽不加卡片）。`?theme=orange` 或 `?theme=%23ffd400` 可临时预览。

```

```
